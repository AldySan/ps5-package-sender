# antislop audit 002 — PS5 Package Sender (runtime)

- **Date:** 2026-11-11
- **Scope:** the runtime data path — `RangeFileServer`, `TransferQueue`,
  `ReceiverClient`, `QueueModel`, `PkgInfo`, `Discovery`, `LibraryScanner`,
  `Database`, `Application` (about 4,500 lines, read in full), plus the
  queue/file-server tests.
- **Method:** full code inspection against the console's measured downloader
  behavior (ShellCore: 64 KiB block ranges, query strings, keep-alive) and the
  receiver payload's wire contract (`/api/status` fields, staged-install
  phases). The app was not executed; interactive flows are covered by the
  queued-script test harness in `tests/queuetest.cpp`.
- **Companion audit:** the receiver payload has its own findings in
  `ps5-package-receiver-elf` (`docs/audit-002-runtime-2026-11-11.md`); two
  findings there (last-install persistence, copy resume) pair with F-1/F-2
  below.

Priority follows the audit 001 tiers: HIGH = wrong user-facing outcome or a
hang/crash, MEDIUM = wrong outcome under real conditions, LOW = hardening.

---

## HIGH

### 1. F-1 — an install whose outcome is unknown is reported as "installed"
`TransferQueue::onReceiverStatus` closes an `Installing` row on an idle
console as `Done "installed"` whenever the receiver's last-install record is
absent or belongs to another URL. Both cases occur in practice: the receiver
keeps that report in memory only, so a re-injected or crashed receiver comes
back with no record at all, and two installs finishing close together can
overwrite each other's record before the 1s poll observes it. A receiver that
died mid-install thus produced a confirmed "installed" row for an install
that never finished.
Fix: fixed — the row now closes as `Done "installed (outcome unreported)"`
when there is no matching report (PR #100, with the receiver-side persistence
in receiver PR #80 removing the common case).

### 2. F-2 — a silently dead download hangs the row forever
A `Downloading` row whose download dies without an error report previously
relied on one of two signals: the receiver going offline (3 missed polls,
requeue) or a last-install report arriving. Neither fires when the receiver
is re-injected *between* two polls: it comes back online idle, with no job,
no report, and no bytes ever moving — the row sat in "console is
downloading…" forever, the same visible symptom class as the range-semantics
bug fixed in #97.
Fix: fixed — a stall watchdog fails the row after five minutes without a
served byte or an install-phase report on an idle console that is not
running our job (PR #100).

## MEDIUM

### 3. F-3 — unbounded recursion on pipelined requests
`ServerConnection::finish()` re-entered `readHeader()` synchronously, so a
client that pipelines N requests in one batch produced N levels of recursion.
A hostile LAN client (or a buggy one) stacking tens of thousands of requests
could overflow the stack and crash the app.
Fix: fixed — the next-request pickup is one queued invocation, draining any
backlog iteratively; a 500-request pipelining test guards it (PR #101).

## LOW (deferred, no code change)

### 4. F-4 — CI portable artifacts ship the test executables
`build.yml` configures `-DBUILD_TESTS=ON` and the deploy steps copy the
whole `build/bin/Release` folder, so the portable zips handed out for testing
contain `fileservertest.exe`, `librarytest.exe` and friends. Release builds
are unaffected (tests are not built there). Harmless but noisy for anyone we
hand a dev build to; the deploy step could exclude `*test*` binaries.

### 5. F-5 — `QueueItem::pullWasActive` is written but never read
`TransferQueue::onReceiverStatus` sets it on every matching pull status; no
reader exists. Left in place (dead fields are only removed in the block that
owns them); worth deleting next time that area is reworked.

### 6. F-6 — request-line split is space-delimited
`readHeader()` splits the request line on single spaces, so a path containing
a literal (unencoded) space truncates into a 404. Sony's downloader
percent-encodes its paths, so this is robustness only.

## Verified clean (no action)

- **Range semantics** post-#97: clamped overshoot, suffix ranges, both 416
  forms, multi-range fallback, fixed validators — all present and covered by
  `tests/fileservertest.cpp`.
- **PkgInfo parsing**: every container/entry/name-table read is bounds-checked
  and capped (64 Ki entries, 4 MB name table, 8 MB icons); no seek/read can
  escape the file.
- **`ReceiverClient`**: every request carries a transfer timeout, so queue
  callbacks always run exactly once; JSON number parsing goes through double
  (exact to 2^53, far above disk and package sizes).
- **`LibraryScanner`**: runs on its own named SQLite connection in the worker
  thread (the default connection is never touched cross-thread).
- **Space pre-flight** (#80-era): warns before pushing when the console has
  less than twice the package free; the push still goes out.
- **`QueueModel::PercentRole`**: guards zero sizes; the staged bar counts both
  console-side copies against twice the size.
