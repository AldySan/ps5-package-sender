# antislop audit 001 — PS5 Package Sender

- **Date:** 2026-11-10
- **Mode:** after (session choice)
- **Scope:** QML UI (`qml/**`) and user-facing C++ strings (`src/**`)
- **Method:** full code inspection of all 12 QML files and C++ UI strings; WCAG 2.1
  contrast ratios computed programmatically from the exact `Theme.qml` values.
  The app was NOT executed (headless environment), so interactive verification is
  by code inspection, per the R-35 fallback for unrunnable deliverables.
- **Direction (owner-supplied):** modern minimalist, clean, professional; brand
  soul: comfort and ease.
- **Design Read:** "Reading this as: a desktop file-transfer utility for PS5
  owners, in a modern minimalist, clean, professional style, dial
  ENERGY 1 / RHYTHM 2 / MOTION 1."

Priority follows the rule tier: Hard Gate = HIGH, Purpose-Gate = MEDIUM,
Quality Locks = LOW. Nothing below has been changed yet; fix only approved
numbers.

---

## HIGH — Hard Gate

### 1. R-02 — em dash in 22 user-facing strings
The banned `—` appears in UI copy across both languages of the codebase.
Evidence: QML (6) `StatusBar.qml:28`, `LibraryPage.qml:181`,
`QueuePage.qml:73`, `SettingsPage.qml:248,262,275`; C++ `tr()` (16)
`Application.cpp:54,126,241,285,420,478,563,573,589,592,593,599`,
`Discovery.cpp:189,190`, `TransferQueue.cpp:83,160,395`.
Fix: rewrite each with comma, colon, or period; keep meaning intact.

### 2. R-25 — white text on accent buttons fails AA
`#ffffff` on the accent is **3.81:1** (needs 4.5) with the default `#2d7ff9`,
on the app's primary CTAs: **Send PKG** (highlighted) and **Download %1**.
All five selectable accents fail as button fills: `#2d7ff9` 3.81,
`#7c5cff` 4.35, `#e0517d` 3.72, `#ee8034` 2.70, `#26a269` 3.25.
Fix: darken the accent used for fills (or flip to accentSoft fill + AA-safe
accent text) so white-on-fill passes 4.5 for every offered accent.

### 3. R-25 — accent used as text fails AA
`#2d7ff9` as text color fails on 7 dark-mode spots (3.28–4.22) and 8
light-mode spots (2.96–3.81): active nav tab, active filter chip, INSTALL
badge (9px), PS5 platform badge (10px), queue active stateText and percent,
catalog URL (11px mono). The codebase already contains the fix pattern: the
light-mode link token uses `Qt.darker(accent, 1.4)` = `#205bb2` → **5.96:1
PASS**. Fix: a theme-aware `accentText` token (dark: lighter variant,
light: darker variant, like the existing link color) used wherever accent
colors text.

### 4. R-25 — light theme status colors below AA
In light mode: ok `#1f9d61` 2.91–3.47, warn `#b97d10` 2.81–3.50,
error-on-background 4.37, muted on surfaceAlt 4.17, muted on chip 4.01.
The dark theme passes the same roles; the light theme systematically does not
(16 computed failures vs 7 in dark, most status-colored).
Fix: darken the light-mode `ok`/`warn`/`error`/`textMuted` values one step
until every computed pair passes.

### 5. R-32 — no visible keyboard focus on the custom button family
`AppButton`, the nav tabs, the filter chips, and the theme toggle all replace
`background` without any `activeFocus`/`visualFocus` state: Tab reaches them,
but focus is invisible. `AppTextField` and `AppComboBox` already draw a 2px
accent focus border, so the intent exists and the button family is the gap.
Fix: add a focus border state to `AppButton` and the three inline button
styles.

### 6. R-32 / R-39 — mouse-only interactive controls
Four controls cannot be operated by keyboard:
- accent color swatches, `SettingsPage.qml:85-101` (MouseArea-only, no
  accessible names);
- console rows in the Detect popup, `StatusBar.qml:188-231` (MouseArea-only,
  no keyboard alternative at all — worst offender);
- catalog URL copy label, `StatusBar.qml:53-65` (MouseArea-only, no visible
  affordance beyond the cursor);
- GameCard body click, `GameCard.qml:15-19` (mitigated by its checkbox).
Fix: replace MouseAreas with focusable controls (Button/ItemDelegate) or add
keyboard handling and accessible names.

### 7. C-4 / R-35 — modal scrim is silently broken
`StatusBar.qml:135-137`: `Overlay.modal` colors `"#000000b0"` / `"#00000059"`
parse as Qt's `#AARRGGBB` → alpha `0x00` → **fully transparent** (verified
against the QML color type documentation; the intended translucent black was
written in web-CSS `#RRGGBBAA` habit). Every modal dialog (custom scan path,
console picker) renders with no dimming at all.
Fix: `"#b0000000"` / `"#59000000"`, or `Qt.rgba(0, 0, 0, 0.69)`.

## MEDIUM — Purpose-Gate

### 8. R-01 / R-20 — default accent has no identity
`#2d7ff9` sits one hue-step from Tailwind's default blue `#3b82f6`; the
swap-the-logo test fails (the UI could belong to any utility). A PS5 product
has a native identity anchor available (the PlayStation blue family), and the
reason for the current choice is written nowhere (no `DESIGN.md`).
Additionally, 4 of the 5 offered swatches can never pass AA in their current
uses (findings 2–3), so the customization feature ships choices that degrade
accessibility. Fix: choose an identity accent with a written reason, and gate
or adjust the swatch set for AA.

### 9. R-39 — comfort: micro type and tiny targets
COPY/INSTALL badges at 9px, history remotePath at 10px; GameCard "🔗" and "✕"
buttons 22px tall; queue "↑"/"↓" buttons lack the ToolTips their siblings
have. Against the stated brand soul (comfort and ease), these are the first
comfort killers. Fix: an 11px floor for badge/meta text, a 28px floor for
icon buttons, tooltips on every icon-only button.

### 10. C-4 — StatusBar overflows at narrow window widths
With Share enabled, the status bar holds roughly 1.1k px of fixed content
(catalog URL is an unelided mono Label, combo fixed at 200px, IP field at
130px) against 872 px available at the 900px minimum width, clipping the
right-side controls (Test/Detect); even the default 1180px window retains
only ~30px of slack. Fix: elide and cap the optional labels, allow optional
items to collapse at narrow widths.

### 11. R-39 — missing hover feedback, weak disabled state
Nav tabs, filter chips, and the theme toggle have no hover feedback at all
(the background only changes when active); `AppButton`'s disabled state is
opacity 0.5 alone. Fix: a hover tint for the three, a stronger disabled
treatment (e.g. muted text + flat surface).

### 12. R-04 / C-4 — icon glyphs render inconsistently per platform
"🔗" renders as a full-color Windows emoji on every GameCard (the app's
primary platform), breaking the monochrome minimalist look; "✕ ⏸ ▶ ↻ ↑ ↓ ☀ ☾"
depend on system font coverage and differ between Windows and Linux.
Fix: a small inline SVG icon set in one consistent stroke weight (or short
text labels).

## LOW — Quality Locks

### 13. R-29 / C-1 — hardcoded colors bypass the Theme tokens
`"#22f5b83d"`, `"#332d7ff9"`, `"#33f5b83d"` (badges) and the scrim colors
from finding 7 are written inline instead of as `Theme.qml` tokens; the
PS5/INSTALL badge tints also ignore the user-selected accent (they stay blue
under an orange accent). Fix: move to Theme tokens derived from
`Theme.accent`/`Theme.warn`.

### 14. R-31 / C-1 — microcopy consistency
"Share on" reads as a state while "Share to console" reads as an action on
the same control; placeholders mix lowercase ("console IP", "pick a scan
path") with sentence case elsewhere; history status "ok" is lowercase beside
the uppercase COPY/INSTALL badges. Fix: pick one convention and apply it.

## What already passes (evidence)

- **R-26:** no dead controls — every button, toggle, and field in all 12 QML
  files has a real handler (code-inspected).
- **R-24:** navigation is Library / Queue / History / Settings; all four
  pages exist.
- **R-17 / R-18 / C-5:** no fake statistics, testimonials, or trust claims
  anywhere in the product.
- **R-29:** a disciplined palette: neutrals + 1 accent + 3 semantic statuses.
- **R-11:** a consistent radius system (8 cards / 6 controls / 4 badges / 3
  progress).
- **R-21 / R-34:** the light/dark toggle exists and every component reads
  Theme tokens (contrast issues aside, findings 3–4).
- **R-27:** empty states on all four pages; scanning and busy indicators;
  queue failure states with retry; the detect popup has busy, empty, and
  cancel handling.
- **R-23:** honest placeholders — titleId initials instead of fake cover art.
- **R-19:** motion is confined to toast enter/exit (180–220ms), consistent
  with MOTION 1.
- **No slop patterns:** zero gradients, glassmorphism, glow, bento grids, or
  fake terminals; badges carry real statuses; no generic AI icon set look.
- **R-33:** everything is built in source; no patch scripts.
- **Comments:** sparse and placed only where logic is non-obvious (the
  StatusBar binding-reestablishment comment is exemplary).
